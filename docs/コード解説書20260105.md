## システム概要

### 目的
文字間のスペーシング（カーニング）を自動調整するWebアプリケーション。ルールベース（Phase0）と機械学習（Phase1）を組み合わせ、Phase2で全体最適化を行う。

### 技術スタック
- **フロントエンド**: HTML5, CSS3, JavaScript (ES6+)
- **描画**: Canvas API
- **データ保存**: LocalStorage API
- **フォント検出**: Local Font Access API（フォールバックあり）

### ファイル構成
```
phase0-demo.html          # メインアプリケーション（単一HTMLファイル）
kerning_categories.json   # 文字カテゴリ定義とペア補正値
assets/phase1_model.json  # 学習済みモデル（Phase1用）
```

## 主要モジュール

### 1. 文字特徴分析モジュール（CharFeatureResolver）

#### 関数一覧

##### `getCharCategory(char: string): string`
文字のUnicode範囲から文字種を判定。

```javascript
// 戻り値: "KANJI" | "HIRAGANA" | "KATAKANA" | 
//         "LATIN_UPPER" | "LATIN_LOWER" | "SYMBOL"
```

##### `analyzeCharWithCanvas(char, fontId, fontSize): Object`
Canvas APIを使用して文字の形状を分析。

**処理フロー:**
1. Canvasに文字を描画
2. ピクセルデータを取得
3. 黒ピクセルの範囲を検出
4. 特徴量を計算

**戻り値:**
```javascript
{
  width: number,              // 実際の描画幅（px）
  height: number,            // 実際の描画高さ（px）
  fillRatio: number,         // 黒密度（0.0-1.0）
  aspectRatio: number,       // 縦横比
  inkLeft: number,           // インク領域の左端
  inkRight: number           // インク領域の右端
}
```

##### `resolveCharFeatures(char, fontId, fontSize): Object`
文字の特徴量を自動判定（キャッシュ機能付き）。

**キャッシュキー:** `${fontId}:${char}:${fontSize}`

**戻り値:**
```javascript
{
  width: number,
  height: number,
  fillRatio: number,
  aspectRatio: number,
  charType: string,          // "VERTICAL_HEAVY", "CURVE", "LATIN_UPPER" など
  density: string,           // "HEAVY" | "MEDIUM" | "LIGHT"
  charCategory: string,      // "KANJI" | "HIRAGANA" など
  actualBoundingBoxLeft: number,
  actualBoundingBoxRight: number,
  actualWidth: number,
  inkLeft: number,
  inkRight: number
}
```

**文字タイプ判定ロジック:**
- 漢字: `aspectRatio < 0.7` → `VERTICAL_HEAVY/LIGHT`, それ以外 → `COMPLEX`
- かな: `fillRatio < 0.3 && aspectRatio 0.8-1.25` → `CURVE`, それ以外 → `KANA`/`DIAGONAL`
- アルファベット: `LATIN_UPPER` / `LATIN_LOWER`

### 2. カーニング計算モジュール

#### Phase0カーニング

##### `getKerningPhase0(leftChar, rightChar, fontName, baseWidthPx, styleId, globalTracking, beforeKerningGap): number`

**計算式:**
```javascript
// 基本ギャップ
base = baseTracking[fontFamily][styleId] || 0

// beforeKerningGapに応じてスケール
if (base === 0) {
  base = DEFAULT_PHASE0_BASE * scaleFactor
}
base = base * (beforeKerningGap / DEFAULT_BEFORE_KERNING_GAP)

// ペア補正値取得（優先順位）
pairAdj = getPairAdjustmentFromJSON(pairCat, fontName)
  || pairCategoryAdjust[pairCat] || 0

// 最終ギャップ
if (TEST_IGNORE_CHAR_WIDTH) {
  gap = base * baseWidthPx + (pairAdj + densAdj) * baseWidthPx + globalTracking
} else {
  gap = base * baseWidthPx + (pairAdj + densAdj) * avgWidth + globalTracking
}

// クランプ
gap = Math.max(-0.2 * baseWidthPx, Math.min(0.8 * baseWidthPx, gap))
```

**補正値取得の優先順位:**
1. `font_overrides[fontName].pair_adjustments[pairCat]`
2. `pair_adjustments[pairCat]`（共通ベース）
3. `pairCategoryAdjust[pairCat]`（コード内フォールバック）

#### Phase1カーニング

##### `getKerningPhase1(leftChar, rightChar, fontName, baseWidthPx, globalTracking, beforeKerningGap): number | null`

**検索優先順位:**
1. `phase1Model[fontName][pairKey]`（フォント名で直接検索）
2. `phase1Model[normalizedName][pairKey]`（長音符をハイフンに変換）
3. `phase1Model[fontKey][pairKey]`（カテゴリで検索: Mincho/Gothicなど）

**未学習ペアの処理:**
- `unlearnedPairAlgorithm === "average"`: 学習済みペアの平均値を使用
- `unlearnedPairAlgorithm === "phase0"`: Phase0にフォールバック（nullを返す）
- `unlearnedPairAlgorithm === "phase0_scaled"`: Phase0の値に係数をかけて調整

**ギャップ計算:**
```javascript
// gap_actual_avgを使用する場合（推奨）
fontSizeScale = baseWidthPx / learnedFontSize
gapPx = gapActualAvg * fontSizeScale

// LATIN_PAIRの場合は追加補正
if (pairCat === "LATIN_PAIR") {
  gapPx += pairCategoryAdjust["LATIN_PAIR"] * avgWidth
}

return gapPx + globalTracking
```

#### Phase2補正

##### `adjustCenterOfMass(gaps, positions, features, fontSize, strength): Object`

重心補正を適用。文字列の視覚的重心を中央に寄せる。

**計算式:**
```javascript
// 各文字の重み = 黒密度 × 文字幅
weights[i] = fillRatio[i] * width[i]

// 重心位置
centerOfMass = Σ(charCenter[i] * weights[i]) / Σ(weights[i])

// 文字列中心
textCenter = (textLeft + textRight) / 2

// 調整量
deltaCenter = textCenter - centerOfMass
adjustmentRatio = (deltaCenter / textWidth) * strength

// 各ギャップに線形に適用
adjustment[i] = adjustmentRatio * textWidth * (2 * positionRatio - 1)
gaps[i] += adjustment[i]
```

##### `smoothGapDistribution(gaps, features, fontSize, threshold, smoothingStrength): Object`

標準偏差補正を適用。ギャップのばらつきを均す。

**計算式:**
```javascript
// 標準偏差計算
stdDev = sqrt(variance(gaps))

// 閾値（2.0px）を超える場合のみ適用
if (stdDev > threshold) {
  // 3点移動平均
  windowAvg[i] = (gaps[i-1] + gaps[i] + gaps[i+1]) / 3
  smoothedGaps[i] = gaps[i] * (1 - strength) + windowAvg[i] * strength
}
```

##### `applyTripletAdjustment(gaps, features, chars, fontFamily, fontSize): Object`

Triplet補正を適用。3文字以上の連続パターンに特別な調整。

**パターン:**
- `VERTICAL_VERTICAL_VERTICAL`: +0.3px（広げる）
- `CURVE_CURVE_CURVE`: -0.2px（締める）
- `BRUSH_SEQUENCE`: +0.4px（緩くする）
- 同じペアカテゴリが連続: ペアカテゴリに応じた補正

### 3. 位置計算モジュール

##### `computeKerningPositions(text, fontId, fontSize, styleId, globalTracking): Object`

文字列全体のカーニング位置を計算。

**処理フロー:**
1. 各文字の特徴量を取得
2. 各ペアのギャップを計算
3. 幅アンカー適用（有効な場合）
4. Phase2補正適用（有効な場合）
5. マニュアル調整適用（有効な場合）
6. 位置を計算

**位置計算:**
```javascript
// 最初の文字の位置
x = startX - getInkLeft(features[0])
positions[0] = x

// 2文字目以降
for (i = 0; i < gaps.length; i++) {
  currentRightEdge = x + getInkRight(features[i])
  nextLeftEdge = currentRightEdge + gaps[i]
  x = nextLeftEdge - getInkLeft(features[i+1])
  positions[i+1] = x
}
```

**戻り値:**
```javascript
{
  positions: number[],        // 各文字のX座標
  gaps: number[],             // 各ペアのギャップ（最終値）
  autoGaps: number[],         // 自動計算されたギャップ
  pairAdjusts: number[],      // ペア補正値
  densityAdjusts: number[],   // 密度補正値
  pairCategories: string[],    // ペアカテゴリ名
  features: Object[],         // 各文字の特徴量
  base: number,               // 基本トラッキング
  fontFamily: string,          // フォントファミリー
  totalWidth: number,         // 文字列全体の幅
  isLearned: boolean[],       // 各ペアが学習済みか（Phase1時）
  evaluationData: Object      // 評価用データ
}
```

### 4. 幅アンカーモジュール

カーニング前後の文字列幅を一致させる。

**処理フロー:**
```javascript
// 1. カーニング前の幅を計算
widthWithoutKerning = calculateWidthWithoutKerning(text, fontId, fontSize, beforeKerningGap)

// 2. カーニング後の幅を計算
totalWidth = computeKerningPositions(...).totalWidth

// 3. 幅の差分
deltaW = widthWithoutKerning - totalWidth

// 4. 比例按分で各ギャップに調整
totalGapSum = Σ|gaps[i]|
if (totalGapSum > 0.001) {
  gapRatio[i] = |gaps[i]| / totalGapSum
  gaps[i] += deltaW * gapRatio[i]
} else {
  // 均等按分
  gaps[i] += deltaW / gaps.length
}

// 5. 位置を再計算
```

### 5. マニュアル調整モジュール

##### `getManualDeltaNorm(fontId, pairKey): number`
フォントサイズに対する比率で保存された調整値を取得。

##### `setManualDeltaPx(fontId, pairKey, deltaPx, fontSize): void`
調整値をpx単位で設定（内部的に比率に変換して保存）。

**データ構造:**
```javascript
{
  "フォント名": {
    "文字1|文字2": {
      "delta_norm": 0.05  // フォントサイズに対する比率
    }
  }
}
```

**保存場所:** LocalStorage（キー: `manualKerningAdjustments_v1`）

## アルゴリズム詳細

### ペアカテゴリ判定

##### `getPairCategoryFromChars(leftChar, rightChar): string | null`

**処理フロー:**
1. 各文字のカテゴリを取得（`getCharKerningCategory`）
2. 大文字・小文字を判定（`getCharCaseType`）
3. ペアカテゴリ名を生成

**命名規則:**
- 同じカテゴリ: `OUTWARD_OUTWARD`
- 異なるカテゴリ: アルファベット順で統一（`ENCLOSED_INWARD`）
- ケース情報: `_UPPER_UPPER`, `_LOWER_LOWER`, `_UPPER_LOWER`, `_LOWER_UPPER`

### 補正値取得

##### `getPairAdjustmentFromJSON(pairCat, fontName): number | null`

**処理フロー:**
1. ペアカテゴリ名からベース名とケース情報を分離
2. フォント別上書きを検索（`getPairAdjustmentsForFont`）
3. 共通ベースを検索
4. ケース情報に応じた補正値を取得

**ケース情報の処理:**
- `_UPPER_UPPER` → `uppercase_uppercase`
- `_LOWER_LOWER` → `lowercase_lowercase`
- `_UPPER_LOWER` → `uppercase_lowercase`
- `_LOWER_UPPER` → `lowercase_uppercase`
- ケース情報なし → `uppercase_uppercase`（デフォルト）

### フォント名正規化

##### `normalizeFontName(fontName): string`

**処理フロー:**
1. `fontFamilyMap`で直接検索
2. 長音符をハイフンに変換して検索
3. 部分一致で判定（mincho/明朝 → Mincho, gothic/ゴシック → Gothic）
4. デフォルト: "Gothic"

**戻り値:** `"Mincho" | "Gothic" | "MaruGothic" | "Brush" | "Script" | "Design"`

## パフォーマンス最適化

### キャッシュ機能
- 文字特徴量: `${fontId}:${char}:${fontSize}`をキーにキャッシュ
- フォント検出結果: セッション中は再利用

### 非同期処理
- フォント検出: バッチ処理でUIをブロックしない
- モデル読み込み: `async/await`で非同期読み込み

### 描画最適化
- Canvas描画は必要時のみ実行
- マニュアル調整のスピンボタン長押し時はテーブル更新を抑制

## 拡張性

### 新しいカテゴリの追加
1. `kerning_categories.json`の`kerning_categories`に追加
2. `pair_adjustments`にペアカテゴリを追加
3. 必要に応じて`font_overrides`にフォント別設定を追加

### 新しい補正アルゴリズムの追加
1. Phase2の補正関数を追加（例: `adjustNewFeature`）
2. `computeKerningPositions`内で呼び出し
3. UIに設定項目を追加（Phase2設定タブ）

### 新しいフォントファミリーの追加
1. `fontFamilyMap`にフォント名を追加
2. `baseTracking`に基本トラッキング値を追加
3. `normalizeFontName`に判定ロジックを追加
