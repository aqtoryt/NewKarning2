## はじめに

### このアプリケーションについて

カーニングエンジンは、文字間のスペーシング（カーニング）を自動調整するWebアプリケーションです。フォントの種類や文字の組み合わせに応じて、視認性の高い文字間隔を計算します。

### 主な機能

- **Phase0（ルールベース）**: 文字の形状特徴から自動計算
- **Phase1（学習値）**: 機械学習で最適化された値を使用
- **Phase2（全体最適化）**: 重心補正、標準偏差補正、Triplet補正
- **マニュアル調整**: 個別の文字ペアを手動で調整

### 対応ブラウザ

- Chrome/Edge（推奨）: Local Font Access API対応
- Firefox/Safari: フォールバック検出を使用

## 基本的な使い方

### 1. アプリケーションの起動

1. `phase0-demo.html`をブラウザで開く
2. ページが読み込まれるまで待つ（フォント検出が完了するまで数秒かかる場合があります）

### 2. 基本的な操作

#### 文字列の入力
1. 「基本設定」タブの「文字列」欄に文字を入力
2. 半角アルファベットは自動的に全角に変換されます

#### フォントの選択
1. 「フォント」ドロップダウンから選択
2. または「カスタムフォント名」欄に直接入力

#### カーニングモードの選択
1. 「カーニングモード」ドロップダウンから選択
   - **Phase0**: ルールベースのカーニング
   - **Phase1**: 学習値ベースのカーニング
   - **比較モード**: Phase0とPhase1を左右に並べて比較

#### 結果の確認
- 左側のCanvas: カーニング前（固定トラッキング）
- 右側のCanvas: カーニング後（選択したモード）

## 設定項目の説明

### 基本設定タブ

#### カーニングモード
- **Phase0（ルールベース）**: 文字の形状特徴から計算
- **Phase1（学習値）**: 学習済みモデルから最適値を取得
- **比較モード（Phase0 vs Phase1）**: 左右に並べて比較

#### 文字列
カーニング対象の文字列を入力。半角アルファベットは自動的に全角に変換されます。

#### フォント
使用するフォントを選択。Local Font Access APIが利用可能な場合は、インストール済みフォントが一覧表示されます。

#### カスタムフォント名（直接入力可）
フォント名を直接入力できます。セレクトボックスにないフォントを使用する場合に便利です。

#### スタイル
フォントファミリーとスタイルの組み合わせによる基本トラッキングを選択：
- **デフォルト**: 基本トラッキングなし
- **和モダン**: 明朝系で-0.5px
- **北欧**: 明朝系で+0.5px
- **モダン**: ゴシック系で-0.3px
- **カジュアル**: ゴシック系で+0.3px

#### フォントサイズ (px)
文字のサイズを指定（20px～200px）。

#### カーニング前の文字間（px）
固定トラッキングの値を設定。スライダーで調整（実効値は表示値の0.2倍）。

#### Phase0幅アンカー（Phase0モード時のみ表示）
カーニング前の文字列幅に合わせて、カーニング後の幅を調整します。
- **有効**: カーニング前後の幅が一致
- **無効**: 個別の補正値調整が反映される（幅は一致しない場合がある）

---

### Phase1設定タブ

#### 未学習ペアの処理方法（Phase1モード時）
学習データにない文字ペアの処理方法を選択：

- **未学習ペアに平均値を使用**: 学習済みペアの平均値を使用
- **Phase0のルールベースにフォールバック**: Phase0の計算値を使用
- **Phase0のルールベース × 係数（幅に応じた調整）**: Phase0の値に係数をかけて調整

#### 未学習ペアを可視化（Phase1モード時）
チェックを入れると、未学習ペアの文字間に赤い線が表示されます。

#### Phase0とのブレンド比率（Phase1モード時）
Phase0とPhase1のブレンド比率を設定：
- **0%**: Phase0のみ
- **55%**: Phase0 45% + Phase1 55%（デフォルト）
- **100%**: Phase1のみ

---

### Phase2設定タブ

#### Phase2: 全体最適化を有効化（Phase1モード時）
Phase2の全体最適化機能を有効にします。

#### 重心補正を有効化（Phase2時）
文字列の視覚的重心を中央に寄せる補正を適用します。

#### 標準偏差補正を有効化（Phase2時）
ギャップのばらつきが大きい場合（標準偏差 > 2.0px）、移動平均フィルタで均します。

#### Triplet補正を有効化（Phase2時）
3文字以上の連続パターンに特別な調整を適用：
- 縦線×縦線×縦線: 広げる
- 丸×丸×丸: 締める
- 筆文字連続: 緩くする

---

### 詳細設定タブ

#### 全体トラッキング調整
すべての文字間隔に一律で加算する値（-50px～+50px）。

---

### マニュアル調整パネル

#### マニュアル調整を有効化（最終ギャップに加算）
チェックを入れると、マニュアル調整が最終ギャップに適用されます。

#### 調整方法
1. 各文字ペアの行で、スピンボタン（＋/－）をクリック
2. または数値入力欄に直接値を入力
3. 調整値は自動的に保存されます（LocalStorage）

#### 全リセット
現在のフォントのすべてのマニュアル調整を削除します。

#### エクスポート（JSON）
マニュアル調整データをJSON形式でクリップボードにコピーします。

#### インポート（JSON）
JSON形式のマニュアル調整データを貼り付けて読み込みます。

## kerning_categories.json の設定方法

### ファイルの場所

`kerning_categories.json`は、`phase0-demo.html`と同じディレクトリに配置してください。

### 基本構造

```json
{
  "kerning_categories": [...],    // 文字カテゴリ定義
  "pair_adjustments": {...},      // ペア補正値（共通ベース）
  "font_overrides": {...}          // フォント別上書き
}
```

---

### 1. 文字カテゴリの追加・編集

#### カテゴリの定義

```json
{
  "name": "Outward",
  "uppercase": ["A"],
  "lowercase": [],
  "numbers": [],
  "uppercase_full": ["Ａ"],
  "lowercase_full": [],
  "numbers_full": [],
  "feature": "外向き斜線",
  "feature_en": "Diagonal outward"
}
```

#### カテゴリの種類

- **Outward（外向き斜線）**: A など
- **Inward（内向き斜線・下部空間）**: T, V, W, Y など
- **Parallel（平行直線）**: H, I, M, N, U, X, Z など
- **Enclosed（閉鎖曲線）**: B, D, O, P, Q など
- **Sided（片側開放）**: C, E, F, G, J, K, L, R, S など

#### 新しいカテゴリを追加する場合

1. `kerning_categories`配列に新しいオブジェクトを追加
2. 該当する文字を各配列に追加
3. `pair_adjustments`に新しいペアカテゴリを追加（必要に応じて）

---

### 2. ペア補正値の設定（pair_adjustments）

#### 基本構造

```json
{
  "pair_adjustments": {
    "ペアカテゴリ名": {
      "uppercase_uppercase": 補正値,
      "lowercase_lowercase": 補正値,
      "uppercase_lowercase": 補正値,
      "lowercase_uppercase": 補正値
    }
  }
}
```

#### 補正値の意味

- **負の値**: 文字間を詰める（例: -0.5）
- **正の値**: 文字間を広げる（例: +0.3）
- **null**: 未定義（デフォルト値を使用）

#### ペアカテゴリの命名規則

- 同じカテゴリ同士: `OUTWARD_OUTWARD`, `INWARD_INWARD` など
- 異なるカテゴリ: アルファベット順で統一（例: `ENCLOSED_INWARD`）
- ケース情報: `_UPPER_UPPER`, `_LOWER_LOWER`, `_UPPER_LOWER`, `_LOWER_UPPER`

#### 設定例

```json
{
  "pair_adjustments": {
    "OUTWARD_INWARD": {
      "uppercase_uppercase": -0.53,
      "lowercase_lowercase": null,
      "uppercase_lowercase": null,
      "lowercase_uppercase": null
    },
    "PARALLEL_PARALLEL": {
      "uppercase_uppercase": -0.3,
      "lowercase_lowercase": -0.32,
      "uppercase_lowercase": -0.32,
      "lowercase_uppercase": -0.32
    }
  }
}
```

---

### 3. フォント別上書きの設定（font_overrides）

特定のフォントに対して、`pair_adjustments`の値を上書きできます。

#### 基本構造

```json
{
  "font_overrides": {
    "フォント名": {
      "pair_adjustments": {
        "ペアカテゴリ名": {
          "uppercase_uppercase": 補正値,
          "lowercase_lowercase": 補正値,
          "uppercase_lowercase": 補正値,
          "lowercase_uppercase": 補正値
        }
      }
    }
  }
}
```

#### 設定例1: 特定フォント名で指定

```json
{
  "font_overrides": {
    "08丸三-明朝体": {
      "pair_adjustments": {
        "OUTWARD_INWARD": {
          "uppercase_uppercase": -0.6,
          "lowercase_lowercase": null,
          "uppercase_lowercase": null,
          "lowercase_uppercase": null
        },
        "PARALLEL_PARALLEL": {
          "uppercase_uppercase": -0.35,
          "lowercase_lowercase": -0.37,
          "uppercase_lowercase": -0.36,
          "lowercase_uppercase": -0.36
        }
      }
    }
  }
}
```

#### 設定例2: フォントファミリーで指定（複数フォントに適用）

```json
{
  "font_overrides": {
    "Mincho": {
      "pair_adjustments": {
        "VERTICAL_VERTICAL": {
          "uppercase_uppercase": 0.5,
          "lowercase_lowercase": 0.45,
          "uppercase_lowercase": 0.47,
          "lowercase_uppercase": 0.47
        }
      }
    },
    "Gothic": {
      "pair_adjustments": {
        "LATIN_PAIR": {
          "uppercase_uppercase": -0.35,
          "lowercase_lowercase": -0.38,
          "uppercase_lowercase": -0.36,
          "lowercase_uppercase": -0.36
        }
      }
    }
  }
}
```

#### 検索優先順位

システムは以下の順で`font_overrides`を検索します：

1. **フォント名そのまま**: `"08丸三-明朝体"` → `"08丸三-明朝体"`を検索
2. **長音符/全角ハイフンの表記揺れを正規化**: 
   - `"08丸三ー明朝体"` → `"08丸三-明朝体"`に変換して検索
   - `ー`（長音符）→ `-`（ハイフン）
   - `－`（全角ハイフン）→ `-`（ハイフン）
3. **フォントファミリー**: 
   - `"游明朝"` → `"Mincho"`に正規化して検索
   - 利用可能なファミリー: `Mincho`, `Gothic`, `MaruGothic`, `Brush`, `Script`, `Design`

#### 補正値の優先順位

補正値は以下の順で参照されます：

```
1. font_overrides[フォント名].pair_adjustments[ペアカテゴリ]
   ↓（見つからない場合）
2. pair_adjustments[ペアカテゴリ]（共通ベース）
   ↓（見つからない場合）
3. コード内のpairCategoryAdjust（フォールバック）
```

#### 部分的な上書き

すべてのペアカテゴリを定義する必要はありません。必要なものだけ上書きできます。

```json
{
  "font_overrides": {
    "08丸三-明朝体": {
      "pair_adjustments": {
        "OUTWARD_INWARD": {
          "uppercase_uppercase": -0.6
          // 他のケース（lowercase_lowercaseなど）は未定義
          // → 共通ベースのpair_adjustmentsが使用される
        }
      }
    }
  }
}
```

#### null の明示的な指定

`null`を指定すると、そのケースは未定義として扱われ、共通ベースにフォールバックします。

```json
{
  "OUTWARD_INWARD": {
    "uppercase_uppercase": -0.6,
    "lowercase_lowercase": null,  // 未定義 = 共通ベースを使用
    "uppercase_lowercase": null,
    "lowercase_uppercase": null
  }
}
```

## よくある質問

### Q1: Phase0とPhase1の違いは何ですか？

**A:** Phase0は文字の形状特徴からルールで計算する方式、Phase1は学習済みデータから最適値を取得する方式です。Phase1の方が精度が高い傾向がありますが、学習データにない文字ペアは未学習として処理されます。

### Q2: 未学習ペアの処理方法はどれを選べばいいですか？

**A:** 
- **平均値を使用**: 学習済みペアの平均値を使用するため、比較的安定した結果が得られます
- **Phase0にフォールバック**: Phase0の計算値を使用するため、ルールベースの一貫性が保たれます
- **Phase0 × 係数**: Phase0の値に係数をかけて調整するため、文字列全体のバランスを保ちながら調整されます

### Q3: 幅アンカーとは何ですか？

**A:** カーニング前の文字列幅に合わせて、カーニング後の幅を調整する機能です。カーニングアルゴリズムの特性を保ちつつ、幅を一致させることができます。

### Q4: マニュアル調整はどこに保存されますか？

**A:** ブラウザのLocalStorageに保存されます。ブラウザの設定をクリアすると削除されますので、重要な調整はエクスポート機能でJSONファイルとして保存することをお勧めします。

### Q5: フォントが表示されない場合は？

**A:** 
1. カスタムフォント名欄に直接入力してみてください
2. フォント名の表記を確認してください（例: `08丸三-明朝体` vs `08丸三ー明朝体`）
3. ブラウザの開発者ツールのコンソールでエラーメッセージを確認してください

### Q6: Phase2の各補正はいつ使うべきですか？

**A:**
- **重心補正**: 文字列の視覚的なバランスが悪い場合
- **標準偏差補正**: ギャップのばらつきが大きい場合（標準偏差 > 2.0px）
- **Triplet補正**: 特定の連続パターン（縦線連続、丸連続など）がある場合

## トラブルシューティング

### 問題1: フォントが読み込まれない

**原因:**
- フォント名の表記が異なる
- フォントがインストールされていない
- Local Font Access APIの許可が必要

**対処法:**
1. カスタムフォント名欄に直接入力
2. フォント名の表記を確認（長音符/ハイフンの違い）
3. ブラウザの設定でフォントアクセスの許可を確認

### 問題2: カーニングが適用されない

**原因:**
- Phase1モードでモデルが読み込まれていない
- マニュアル調整が無効になっている

**対処法:**
1. ブラウザのコンソールでエラーメッセージを確認
2. `assets/phase1_model.json`が正しく配置されているか確認
3. マニュアル調整のチェックボックスを確認

### 問題3: 設定が保存されない

**原因:**
- LocalStorageが無効になっている
- ブラウザのプライベートモードを使用している

**対処法:**
1. ブラウザの設定でLocalStorageを有効化
2. 通常モードで使用
3. マニュアル調整はエクスポート機能でJSONファイルとして保存

### 問題4: パフォーマンスが悪い

**原因:**
- フォント検出に時間がかかっている
- 文字特徴量の計算が重い

**対処法:**
1. フォント検出の完了を待つ
2. 文字特徴量はキャッシュされるため、2回目以降は高速化される
3. フォントサイズを小さくする

### 問題5: kerning_categories.jsonの変更が反映されない

**原因:**
- ファイルのパスが間違っている
- JSONの構文エラー
- ブラウザのキャッシュ

**対処法:**
1. `phase0-demo.html`と同じディレクトリに配置されているか確認
2. JSONの構文を確認（カンマの位置、引用符など）
3. ブラウザをリロード（Ctrl+F5 で強制リロード）
